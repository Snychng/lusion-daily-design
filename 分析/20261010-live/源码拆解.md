## 当前场景结构与旧推荐差异

当前首页首屏是 **可碰撞、可被指针推动、点击施加冲量并换色的十字构件群**。宇航员穿越与撞破玻璃仍存在于 `home-goal` 后半段，不是当前首屏。不能把早期推荐中的宇航员描述误写成当前首屏场景。

首页顺序为 Hero 物理构件 → reel 的 UfxMesh 媒体层 → featured projects → goal 文案和图框 → 黑隧道/白隧道/碎玻璃/宇航员落下 → end/footer。About 包含三维粒子与镜头场景、Who 的横向文字和字标变形、团队点云转换、clients/awards/capabilities，以及 end/footer。

**About GPU 粒子、ScreenPaint 屏幕扰动、Footer FlipSim 是三个不同系统。** 它们不能统一称为同一个“流体效果”，也不能只实现其中一个便声称覆盖全部动效。

## 启动、路由与渲染链路

`preRun()` 先初始化 RouteManager，并等待 Aeonik 400 字体；`run()` 初始化 WebGL、Input、ScrollManager、当前 page、UI 和 loader；预载结束进入 `init()` / `start()`。`requestAnimationFrame` 的 dt 上限为 `1/20` 秒，输入、滚动、页面、UI、场景与后处理按原顺序更新。

`RouteManager` 通过 History API 和 XHR 拉取内部 HTML，提取 `.page` 及 page title 后交给 `PageManager`。页面对象有 preload/init/show/hide 生命周期与待处理跳转；返回、退出与二次进入不能用整页 location 跳转代替。root 相对 `/assets` 路径在 localhost 天然可用，因为 CDN 切换只匹配线上 hostname。

品牌版在内容层将 19 项详情换为自有英文 slug，映射见 [routes.json](../../brand-content/routes.json)。`ProjectPage` 的 `/projects/([^/]+)$/` 可直接接受这些 slug，详情缓存使用路径第二段和 DOM 的 `data-id`、`data-next-id`。`ProjectItem` 仍动态拼接 `/assets/projects/<id>/home.webp` 与 `home_depth.webp`；构建先覆盖旧资产路径的品牌媒体，再生成 38 个新缩略图/深度别名。207 个详情 `data-filename` 和媒体映射的原键保持不变，保留的是资产契约，并非品牌版公开路由。原 19 个详情 HTML 仅保留在 `reference/`，品牌构建会移除旧页面并写入自有页面；路由引擎没有为此改写。

`Stage3D` 场景动态写入全局相机/材质/后处理配置。以 renderOrder 排序的主要链路是：GoalTunnelEfx 0 → About prepass 5 → Bloom 10 → About final 20 → Final 30 → PreUfx 50 → ScreenPaintDistortion 75 → PostUfx 100 → SMAA 500 → 可选 FSR 2000。DOM 区域和三维图框由 UfxMesh 同步，遮挡与前后层顺序是机制的一部分。

后处理 shader、Three.js、EXRLoader、fflate 解码逻辑都内嵌在 runtime 中。未发现需要额外远程 Shader 文件、GLTF Draco/KTX 解码器包或独立 worker 文件的这版场景；库内 Blob worker 源码在包内生成。

## 首屏材质与物理

- 桌面 24 个模型（22 个实体、2 个半透明玻璃），移动 UA 为 22 个且不含玻璃。几何 `home/cross.buf` / `cross_ld.buf`，材质 `home/matcap.exr` / `matcap_ld.exr`。
- 实际原文件属性为 `daoN/normal/SN/ao/daoP/indices/position/thickness`，见 [source/geometry-schemas.json](source/geometry-schemas.json)。原包无 uv attribute，不应根据 Three 标准材质习惯增加“必须有 uv”的不实要求。
- Shader 为每个构件接收其他构件的 position/radius/quaternion/color/transparency；`getCrossAoShadowIntersect` 明确按三根正交圆柱近似十字形的邻居 AO、阴影与反射。圆柱长参数约 `.666667×radius`，横向约 `.333333×radius`。
- 玻璃 IOR 2.4，前后面单独绘制；从先渲染的背景采样四级模糊。球形包围碰撞半径 `1.05×radius`，中心引力 40，速度衰减 `pow(.2,dt)`，有质量、摩擦和恢复系数。
- 指针射线推动参数 `.025/.1/.12`；点击同时轮换 palette、翻转黑白和对所有刚体施加反向速度及随机冲量。仅点击换 CSS 背景不等价。
- 品牌 D 已兼容上述 geometry 属性，并以 `src/models/daily-neighbour-shadow.glsl` 替换十字解析相交函数，使用七笔画 D 邻居代理；它仍是 AO / 柔影 / 反射的解析近似，不与字形网格逐面一致。保留球形物理属于原算法近似，不是新轮廓精确刚体接触。重建与离线验证见 [模型说明](../../src/models/README.md)。

## 宇航员、隧道、碎玻璃与滚动

滚动阶段 `blackFrameShow → blackFrameIn → blackTitle → blackTunnel → whiteTunnel → whiteFrameOut → whiteFrameBreak → astronautDrop → astronautWait`。中间六段权重为 `1/5/12/2/1/1.5`，总 22.5；首尾尺寸来自 viewport、图框和 footer 的真实 DOM 距离，所以不能随意删除承载槽位。

按住时 `freezeRatio` 每帧平滑趋近 1，场景时间倍率从 1 降到 .3，自动滚动从原方向 `lastScrollYDirection×2.5` 逐渐降低；松开恢复。逆向滚动改变黑隧道内部时间符号，既影响相机也影响结构运动。

黑隧道使用 `GRID_SIZE=20` 的 HD/LD base 与 structure 实例几何、greeble arm/base/nor，反馈 RT 为画布 1/4。白隧道 16 个 block，Dolly FOV offset 60→0。角色出场后会重挂到 `homePage.preUfxContainer`，与设备图框和玻璃共用分层关系。

宇航员为主角+4 clone、53 骨。每顶点 `boneIndices vec2 / boneWeights vec2`，动画 position/orient 按 frame×53 打包为浮点数据纹理。循环区间 0–89、过渡 90–139、落下后 140–287，采样 60fps；入口/出口额外路径由约100帧的独立 `.buf` 提供。ARM 与 base.r 被重打包成 armb，不能把它们当普通 RGB 颜色纹理。

玻璃是 **946 碎片**，顶点 `piece` ID 查找 frame×946 的位置/旋转纹理；whiteFrameBreak 使用 sineOut，碎片最后随 drop `.75→1` 缩小到0。Shader 用屏幕前帧、导数法线与 reflect 偏移实现折射/彩边，不能用 CSS transform 纸片替代。

## About GPU 场景

About 粒子桌面 `128×192=24,576`，移动 UA `128×128=16,384`，RGBA Float ping-pong。4D simplex 导数 curl、光源 spin、life 重生驱动漂流；它是 GPU 粒子场，**不是完整 Navier–Stokes 求解器**。按住把 intro 时间降到约 .1 倍，noise 时间仍使用常规 dt。

光源 `(0,8,0)`；shadow map 1024×2048；64³ 光场按 8×8 切片装入 512×512 纹理；四档 sphere LOD。还包含岩石碎片、54骨 person、terrain、fog、halo、lines、letters，保留粒子但删掉场景其它层会改变原景深与体积感。

相机读取 `about/camera_spline.buf` position/orient，索引为 `initialSplineRatio×149 + panningSplineRatio×50`。About 桌面段落滚动换算用 viewport 宽度，移动布局使用高度；PAGE_DISTANCE 1.25，起始等待3.5、分段1.75、结束等待2.5。

团队点云为独立双缓冲 morph，每份 8192 点（128×64）、position vec3 + Uint8 nShade vec4，RGB 编码法线、A 编码 shade。原有 glitch、扫描线、指针光照和转头可沿用；将团队数据换成自有实验点云必须同时换 JSON 文案和默认 `faceId="edan"` 的契约。点云 scale `(27.5,27.5,16)`、rotation `(.1,π+.2,0)`、position `(0,34,25)`，新模型需匹配归一化范围/方向。

## Footer FlipSim 与 ScreenPaint

`FlipSim` 在 CPU 中维护网格 u/v 速度、particle position/velocity/density、固体格与碰撞矩形，执行粒子积分、相互推开、粒子→网格速度、压力迭代、网格→粒子速度。`FlipAnimation` 设置 pressure iterations 60、particle iterations 4、over-relaxation 1、**FLIP_RATIO=0（当前参数偏 PIC）**。名称为 FlipSim 不代表实际每帧使用纯 FLIP 混合。

粒子经 InstancedBufferGeometry 绘制为十字、方形、圆形、三角，或 flip_texture.png 的图集实例。桌面 pointer 扰动、按住时 emitter 沿指针轨迹且 flushing 开启；移动布局按住作为障碍推动，不走同一桌面 emission 分支。`#end-bottom` 作为非图集模式的碰撞矩形，删除该节点会改变液体堆积。

ScreenPaint 则是渲染宽高 `/4` 的屏幕速度/权重场，另有 `/8` 缓存，RG 零速度编码 `.5,.5`。运行参数 velocity dissipation .975、weight .95/.8、curlScale .02、curlStrength 3、pushStrength25。移动端需连续按下才绘制；distortion 9次纹理采样、amount3、RGBShift .5。它同时影响 reel、图像/文字材质与最后屏幕折射，不能拿 About 粒子更新代替。

## 响应式与性能分支

| 判断 | 实际用途 |
| --- | --- |
| viewport width <=812 | 主布局、触摸适配和部分事件行为 |
| viewport width <=560 | 首页 reel 横/竖视频切换 |
| ProjectDetailsSection 1000 | 详情横向/竖向编排 |
| browser.isMobile（UA） | 模型LD、移除首页玻璃、粒子数量、移动媒体路径、默认无音频、Bloom分支 |

因此只把桌面窗口调到390px不等于移动 UA测试。桌面与移动版的不同构件数/材质/音频是原版主动降级，需要保留并分别报告。当前代码性能证据仅是配置和复杂度；实际 FPS、长任务与真机发热需独立测量。

## 二进制与品牌适配边界

`.buf` 开头为 uint32 的 JSON header 字节数，随后 JSON，之后属性按记录顺序连续排列。无额外 padding；header 与属性 offset 必须自然满足各 TypedArray 的字节对齐。`indices` 使用 indexCount，其余使用 vertexCount。packed float 的解码使用 `(raw+signedOffset)/2^(8*bytes)*delta+from`。生成新模型可用未压缩 Float32 position 与 Uint8/Float32 辅助属性，但必须按原读取顺序与尺寸输出。

品牌适配层覆盖 DOM/meta/link、About 几何 logo、团队点云/JSON、隧道 stickers、设备截图、项目缩略图/详情媒体与客户奖项槽；宇航员头盔、衣物与像素表情贴图的检查及保留边界见模型说明。About 的 `#about-who-title-main-logo` 是原空 SVG 定位槽，不能追加可见字形，否则与 `logo_text.buf` 重影；其他 SVGLoader 字形必须转为真实 path，奖项标题只读 `paths[0]`，所以所有字母合为一个复合 path。原 `LusionMono` 内部 font-family 名称保留为字体兼容标识，不是可见机构介绍。

原 Newsletter 会真实调用 Mailchimp；品牌构建已移除调用与原 endpoint，保留表单结构并改为 GitHub 入口。原全屏 VideoOverlay 依赖 Vimeo，与首页 reel VideoTexture 不同；品牌构建使用 `src/local-player.js` 的本地 HTML5 媒体兼容层，接回原 overlay 的开合、光标、音量、暂停和进度条机制。实际播放及快速退出结果由浏览器验收记录，不能从适配代码推断全部通过。早期补丁分析保存在 [source/patch-recommendations.md](source/patch-recommendations.md)，完整槽位见 [source/content-slots.json](source/content-slots.json)，主要类提取见 `source/classes/`。

资源下载与静态指纹闭包已经验证；浏览器当前原站访问状态、品牌实现实际画面、反向滚动、返回/重复进入、加载资源和 FPS 由案例总验收补充。本源码分析不宣称逐像素一致，也不证明真实移动设备性能。
